# CS2 官方宠物 Panorama UI 调研

调研日期：2026-09-28。目标：为现有桌宠选择可实现的官方外观和交互方案，保持透明桌面、实时 3D 动画和轻量运行。

## 结论

可以复刻官方宠物界面的视觉、按钮组织和交互规则。推荐继续使用现有 WPF 与 ValveResourceFormat 渲染器，将 Panorama 的布局、样式和动作数据适配为本地控件。

官方 XML、CSS、JavaScript 不能直接作为独立界面运行：它们使用游戏原生预览面板、场景实体、相机和库存接口。ValveResourceFormat 的模型渲染与 Panorama UI 运行时是不同部分。本项目需要接入自己的动作控制、相机和本地设置。

本文件记录调研依据。2026-09-28 首版已实现官方风格悬停工具条、七种具名动作、独立检视、本地命名、PNG 拍照和照片库；复用现有渲染器。原生视线跟随、成长同步、地图场景特效和头饰仍属于后续扩展。

检视体验优化采用官方 `popup_inventory_inspect.xml` 的大幅预览和边缘控制层结构，以及摄影棚的浮动控制栏；移除独立方形预览底板。外观与摄影设置按需切换，名称在标题旁编辑，动作集中到底部。WPF `WindowChrome` 接管完整客户区并提供原生标题拖动；预览的透明像素移动窗口，小鸡像素用于旋转，Shift 可切换为移动窗口。最小化使用横线，相机缩放使用同一线条样式的放大镜加减，避免视频收放图标在不同场景的歧义。

## 2. 官方七种动作与当前动作系统

动作按钮由 `popup_pet_photobooth.js:456` 根据 `PetPhotoTag.ACTIVITIES` 动态创建。点击入口为同文件 `PlayPetActivity()`（522 行），调用原生面板的 `SetPetActivityOnItem()` 或 `SetPetActivityAndVariationOnItem()`。

| 建议中文标题 | 官方语义 | activity | variation | 官方图标 | 当前动画图中的候选剪辑 |
| --- | --- | --- | --- | --- | --- |
| 坐下 | sit | trick | 2 | `pet_activity_sit` | `chick_trick03` |
| 惊慌 | panic | panic | 未指定 | `pet_activity_panic` | Panic 分支中的 `chick_react01` / `chick_react02` |
| 摇尾 | wag | trick | 9 | `pet_activity_wag` | `chick_trick10` |
| 跳舞 | moonwalk；英文标题为 Dance | trick | 5 | `pet_activity_dance` | `chick_trick06` |
| 跳跃 | jump | trick | 11 | `pet_activity_jump` | `chick_trick12` |
| 踢腿 | kick | trick | 12 | `pet_activity_kick` | `chick_trick13` |
| 飞翔 | fly | trick | 1 | `pet_activity_fly` | `chick_trick02` |

activity、variation 和图标来自官方 UI 数据。候选剪辑来自本机 `animation/graphs/chicken/chicken.vnmgraph_c`：`all tricks` 的参数选择器读取 `action_variation`，十三个选项依次关联 `chick_trick01` 至 `chick_trick13`。上表按选项零基顺序推导；尚未在官方场景逐个视觉验证，因此不能仅凭编号将其视为跨版本永久映射。Panic 也不应在没有核对图状态时指定为唯一剪辑。

### 官方可用条件

`popup_pet_photobooth.js:566` 限制动作的成长阶段：

- 坐下、惊慌没有动作年龄门槛。
- 摇尾、跳舞、跳跃至少需要 adolescent 阶段。
- 踢腿、飞翔至少需要 adult 阶段。
- 动作栏还要求单宠物自由姿势；动作运行时其它入口暂停，当前按钮显示忙碌状态。

桌宠中的模型品种和 Steam 库存成长阶段并非同一概念。建议以本机资源与骨架兼容性为可用依据，在界面中明确显示支持情况；若产品要严格模拟官方成长，再增加独立的本地成长规则。

### 已接入的动作系统

原有 `trick`、`trick2` 是通用表演入口。首版已通过 `PetUiResources` 读取官方活动数据和动画图关联，并由 `PetCatalog.ClipCandidates()` 为七种语义动作提供独立候选。

语义键沿用官方的 `sit`、`panic`、`wag`、`moonwalk`、`jump`、`kick`、`fly`；`moonwalk` 的界面标题为“跳舞”。缺少匹配动作时禁用该入口并说明原因，保留 `AnimationController.IsPlayable()` 骨架检查；不会回退为另一种表演。

官方脚本会查询原生活动是否开始或结束，最长 5 秒是按钮忙碌状态的轮询保护。桌宠应继续按剪辑自身时长完成播放，不能把该数值移植为动画截断时间。

## 3. 应沿用的官方视觉规范

实际宠物界面采用灰色半透明面板和小图标：

| 项目 | 官方数值或行为 | 桌宠适配建议 |
| --- | --- | --- |
| 主菜单工具条 | `vanity_pet_info.css:102`：6 px 内边距、8 px 圆角、`rgba(126,126,126,0.15)`；按钮左右间距 6 px | 沿用形状和节奏；提高桌面任意背景上的对比度 |
| 摄影棚面板 | `popup_pet_photobooth.css:68`：8 px 圆角、`rgba(75,75,75,0.6)`，极淡点状纹理 | 使用简洁灰色底板；纹理可以省略 |
| 动作图标 | 摄影棚底栏显示高度 26 px；源码以 32 px 图标纹理创建 | 使用官方图标，按 DPI 缓存合适尺寸 |
| 忙碌状态 | 图标透明度 0.25，显示 26 px Spinner | 同时提供明确的状态提示，动画结束恢复可用 |
| 过渡 | 主菜单布局/宽度过渡约 0.1–0.2 秒 | 悬停展开和收起保持短促，隐藏后停止装饰动画 |
| 字体 | Stratum 系列；文本输入声明 Stratum2 与 Arial Unicode MS | 能从本机合法来源解析时使用；否则使用系统字体并核对字号和字宽 |
| 溢出 | 主菜单面板 `overflow: noclip` | 工具条使用独立 Popup，避免受宠物渲染矩形裁剪 |

`CSGOBlurTarget` 模糊的是游戏场景中的指定区域。桌宠没有这一原生面板；首版可通过稳定的灰色面板实现可读性，无需持续模糊整个桌面。宠物透明合成和 UI 背景应各自处理，避免再引入方框、光晕或羽毛透亮缝隙。

## 4. 推荐的桌面产品结构

### 日常悬停工具条

- 沿用目前约半秒的悬停触发，移开后收起；进入按钮、子菜单或名称输入框时保持显示。
- 主条显示喂食、动作、睡觉/叫醒、检视等少量常用入口，以官方图标、8 px 圆角和灰色面板替换当前 18 px 圆角文字条。
- “动作”展开官方七种命名动作；只显示或启用当前宠物支持的入口。完整蛋和破壳蛋仍使用自身专属能力。
- 放大/缩小、命名、拍照、切换宠物放在展开区域或检视面板，保持日常桌面安静。
- Popup 锚定宠物并限制在当前屏幕工作区内；靠近边缘时调整方向。只让实际 UI 区域接收输入，空白区域保持桌面穿透。
- 保留当前单击、双击、中键、拖动、滚轮和右键菜单，并核对它们与按钮点击的事件冲突。

这是一套桌面适配方案；喂食、睡觉和叫醒的位置是本项目设计，不是声称官方主菜单已有这些按钮。

### 按需打开的检视窗口

使用官方检视/摄影棚风格，提供大图预览、旋转、明确命名的动作、品种和羽色选择。名称可以保存到现有本地设置；照片可以保存到本地相册。

继续使用现有 GPU 渲染链。检视窗口打开期间，可暂停桌面场景并复用渲染器，避免同时维持两个连续渲染循环。关闭后恢复桌宠原位置、大小、朝向与互动状态。

官方 `StartPetLookAt()` 是引擎功能，不能仅复制 JS 后获得。若要增加鼠标视线跟随，需要另做骨骼朝向控制与动画混合，可作为后续增强。

### 摄影棚扩展

可逐步支持拍照、简单滤镜、头饰与背景。官方地图的相机、实体输入、粒子和环境效果需要额外实现与性能评估，不能将整套游戏场景界面视为仅复制布局即可完成的功能。

官方库存命名、成长、食物有效期、寿命、成就、宠物册及照片记录依赖游戏接口。桌宠若提供类似功能，应采用清晰的本地数据模型；当前方案不包含 Steam 库存同步。

## 5. 更新兼容性、轻量化和发布

### 资源与动作

1. 继续从本机 CS2 VPK 发现模型与动画，使用模型路径作为稳定标识，不以菜单排序持久化选择。
2. 为命名动作建立独立描述：语义 ID、候选资源、循环/一次播放、兼容性和取景策略。优先读取当前动画图的活动关联；无法解析时使用已核对的候选并降级禁用。
3. 当前只在内存中缓存，每次启动重新解析本机 VPK；失效图标有替代图形，缺失动作不导致整个宠物加载失败。若将来加入磁盘缓存，应关联 VPK 条目 CRC/版本。
4. 新增动作需要纳入 `PoseBounds` 预计算。日常动作保持共同固定镜头；跳跃、飞翔等大幅动作在开始时选定安全取景，播放期间继续锁定镜头，防止逐渐变大变小和旋转裁切问题复发。
5. 不改变当前羽毛材质、环境光照和 MSAA 透明覆盖率处理。

### UI 资源与运行成本

本机 VPK 已确认存在七种 `pet_activity_*.vsvg_c` 图标。可用 VRF 解码本地资源，缓存成 WPF 可显示的图像。字体的实际资源位置尚未确认，不应假定 CSS 声明等同于发布包可直接使用的字体文件。

WPF 控件和少量缓存图标可以复用当前桌面框架，不需要增加浏览器运行时。避免工具条轮询全部模型或图标；隐藏时不运行 Spinner。是否满足具体内存、GPU 和响应目标，应在实现后与当前版本实测比较，调研阶段不承诺未测得的占用数字。

继续保持单 EXE 发布布局，运行时读取本机游戏资产。Valve 模型、图标、字体和其它提取资源延续当前项目的排除规则；本项目 MIT 源码许可不包含这些游戏资产。原始资源与分析转储放在被 Git 忽略的 `research/`，不提交到仓库或发布包。

## 6. 实施状态与验收

**已完成：官方风格互动栏与命名动作。** `QuickActionBar` 使用官方矢量图标、动作状态与七种语义入口，并保留已有快捷操作。

**已完成：独立检视与本地摄影棚。** 支持大图预览、旋转缩放、外观选择、本地命名、四种背景拍照和照片库，复用同一个渲染器。

**后续扩展：摄影棚增强。** 根据使用情况增加姿势、头饰和滤镜，再评估地图场景与特效。

后续完整产品验收应继续覆盖：

- 每个支持动作的实际内容、完整时长、结束恢复和重复点击行为；区分模型支持与官方年龄门槛。
- 默认小鸡与其它品种反复切换后的动作、材质和光照。
- 大幅动作与各个旋转角度的取景稳定性。
- 白色、黑色和图片桌面上的图标可读性、透明边缘及羽毛细节。
- 100%、125%、150%、200% DPI，多屏和屏幕边缘的菜单位置。
- 鼠标进入子菜单、输入名称、拖动小鸡、退出检视窗口时的焦点与穿透。
- 与当前版本对比静置、互动、菜单隐藏和检视模式的 CPU、GPU、工作集与帧率。

调研依据为本地源码、图标清单、动画图转储及项目接口。首版运行验证已通过：18 个图标解码、七种动作映射、命名与 PNG 保存、八个屏幕边缘位置，以及真实检视窗口中的切换、拍照、关闭和重开。四种鸡与蛋的旋转取景共检查 17,495 帧，未发现裁切或镜头自动缩放。尚未启动游戏内官方摄影棚进行逐项对照。

发布版在正常 Windows 桌面启动，约 3 秒完成初次加载。检视模式短时连续采样多数为 60–62 FPS，单次工作集采样约 339 MB；这是本机当前资源版本下的结果，不能代表所有硬件或长时间运行。受限测试环境曾只有约 10 FPS，因此真实性能采样使用正常桌面进程。发布目录仅含 `ChickenDesktopPet3D.exe`，约 28.1 MiB。
